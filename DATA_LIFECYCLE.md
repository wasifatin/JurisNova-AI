# Data Lifecycle & Processing Architecture
## JurisNova AI — Governance, Risk & Compliance Intelligence Platform

---

## 1. Overview of the Data Lifecycle

JurisNova AI maintains an evidence-first, traceable lifecycle for all ingested organizational policies, regulatory frameworks, compliance findings, and audit trails.

```
[ Ingest & Validate ] ──► [ Extract & Normalize ] ──► [ Chunk & Index ] 
                                                               │
                                                               ▼
[ Delete & Purge ]    ◄── [ Audit & Report ]      ◄── [ Query & Verify ]
```

---

## 2. Ingestion & Validation Phase

### Supported Document Types:
* **PDF (`.pdf`):** Processed via PyMuPDF (`fitz`) for accurate text extraction, page boundary identification, and heading extraction.
* **DOCX (`.docx`, `.doc`):** Processed via `python-docx` extracting paragraph content and using paragraph heading styles as section boundaries.
* **Plain Text (`.txt`, `.md`):** Extracted in logical paragraph groups.

### Validation Gates:
* **Size Limits:** Max upload size $\le 25\text{ MB}$.
* **Extension Whitelist:** Files without approved MIME types or extensions are rejected with HTTP 400.
* **Integrity Hashing:** Files are stored under organization-isolated paths in `./uploads/` with unique timestamp prefixes.

---

## 3. Extraction, Normalization & Chunking

### Normalization Rules:
* Redundant consecutive whitespace and tabs are collapsed.
* Hyphenated line wraps (e.g., `infor-\nmation`) are re-joined into full words (`information`).
* Consecutive newline sequences ($\ge 3$) are normalized to double newlines.

### Chunking Parameters:
* **Strategy:** Sliding window with word-boundary awareness.
* **Chunk Target Size:** 750 characters (~110–130 words).
* **Chunk Overlap:** 150 characters (~20–25 words) to ensure contextual continuity across boundaries.
* **Preserved Metadata:**
  * `document_id`: Parent document UUID.
  * `document_name`: Human-readable document title.
  * `page_number`: Exact source page where the chunk begins.
  * `section_title`: Associated chapter, section heading, or clause number.
  * `chunk_index`: Zero-indexed position in document sequence.
  * `token_count`: Estimated token count.

---

## 4. Vector Embedding & Storage

* **Dimensionality:** 384 dimensions.
* **Offline / Local Engine:** Normalized sub-word n-gram and term-positional hashing providing consistent deterministic vector representations offline.
* **Cloud API Integration:** Configurable via `.env` to leverage Google Gemini `text-embedding-004` or OpenAI embeddings.
* **Persistence:**
  * Local/Demo: Serialized JSON vector arrays in SQLite.
  * Production: `pgvector` vector extension in PostgreSQL with indexed cosine distance operator (`<=>`).

---

## 5. Retrieval, Verification & Retention

### Hybrid Retrieval:
```
Score = (Vector_Cosine_Similarity × 0.65) + (Keyword_Term_Overlap × 0.35)
```

### Citation Verification:
Every claim generated by an agent is subjected to verification:
* **Exact Substring Match:** Yields 1.0 confidence.
* **High Token Overlap ($\ge 70\%$):** Yields verified status.
* **Low Overlap ($< 45\%$):** Flagged as potential hallucination.

### Deletion & Retention Policy:
* **Cascade Deletion:** Deleting a document removes its chunks, versions, and cached embeddings immediately.
* **Audit Trail Persistence:** Deletion events are permanently recorded in `audit_logs` preserving the action, user, and document title.
